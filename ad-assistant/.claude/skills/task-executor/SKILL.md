# 任务单执行 Skill

## 核心规则

**开发前必须执行以下流程，缺一不可：**

### 第一步：读取任务单

```text
强制读取文件（按顺序）：
1. README.md
2. CODEX.md
3. CLAUDE.md
4. tasks/current-task.md
5. 任务单中列出的相关 docs/*.md
```

只有 `tasks/current-task.md` 状态为 `MVP_REQUIRED` 或 `MVP_OPTIONAL`（已确认）时，才能开始开发。

### 第二步：确认任务边界

从任务单中提取并口头确认：

- **本次只开发什么** — 列出功能清单
- **本次不开发什么** — 列出禁止项
- **允许修改哪些文件** — 文件白名单
- **禁止修改哪些文件** — 文件黑名单
- **验收标准** — 完成定义
- **测试方式** — 必须通过的测试
- **是否允许新增依赖** — 依赖规则
- **是否涉及重大变更** — 重大变更判定

### 第三步：执行开发

严格遵守：

- 只修改 `允许修改哪些文件` 中列出的文件
- 不碰 `禁止修改哪些文件` 中的任何文件
- 任务单没写的功能一律不做
- 遇到重大变更立即停止，输出 6 项分析（修改原因、风险点、影响范围、回滚方案、兼容性、是否需要数据库迁移），等待用户确认

### 第四步：完成输出

每次完成任务后必须输出：

- 修改文件列表
- 实现内容
- 未实现内容
- 测试命令和结果
- 风险点
- 是否触发重大变更
- 等待 Codex Review，不得自行提交

## 禁止行为

- 没有任务单写代码
- 超出任务单范围开发
- 自行开发未来功能（BACKLOG / FUTURE）
- 大规模重构
- 自动升级核心依赖
- 删除文件（除非任务单明确授权）
- 重命名目录（除非任务单明确授权）
- 自行提交代码（必须等 Codex Review 通过）

## 重大变更清单

以下任何一项都属于重大变更，必须先输出分析、等待确认：

- 修改数据库表结构
- 修改 API 契约
- 修改 Provider 接口
- 修改授权逻辑
- 修改点数/算力系统
- 修改支付逻辑 / 登录逻辑 / Token 机制
- 修改项目目录结构
- 修改 shared DTO / OpenAPI
- 修改 Tauri 权限配置 / 自动更新逻辑
- 修改本地 Python 服务启动方式
- 引入新第三方 SDK
- 升级核心依赖（Tauri, Vue, TypeScript, Pinia, FastAPI, SQLAlchemy, 数据库驱动, Redis, Celery/RQ, Next.js, Tailwind, AI Provider SDK）

## 安全红线

开发过程中必须确保：

- 不下发 API Key 到客户端
- 不由客户端直接调用第三方 AI API
- 不由客户端扣点
- 不由客户端决定套餐和权限
- 不绕过云端授权
- 不本地保存明文 Token
- 所有云端 AI 调用经过 Provider 层并写入 provider_call_log

# 测试执行 Skill

## 核心规则

测试必须按 `tasks/current-task.md` 中定义的测试方式执行。

不编造测试，不跳过测试，不假装测试通过。

## 测试流程

### 第一步：从任务单提取测试要求

读取 `tasks/current-task.md` 的 **测试方式** 章节，提取：

- 必须执行的测试项
- 测试框架要求
- 覆盖率要求

### 第二步：执行测试

按顺序执行每个测试项：

1. 单元测试
2. 集成测试
3. API 测试
4. 安全测试（无 API Key 泄露、无明文 Token 等）

记录每条测试命令和完整输出。

### 第三步：输出测试报告

必须包含：

```
## 测试报告

### 测试环境
- 操作系统
- 运行时版本
- 相关依赖版本

### 测试结果

| 测试项 | 命令 | 结果 | 输出摘要 |
|--------|------|------|---------|
| xxx    | xxx  | ✅/❌ | xxx     |

### 未通过测试
- 测试项名称
- 失败原因
- 建议修复方案

### 未覆盖风险
- 未测试的场景
- 原因（时间限制 / 环境限制 / 任务单未要求）
- 潜在影响

### 验收标准对照
```

## Sprint-01 必须的测试

登录授权：
- 云端 Auth API 测试（login / refresh / logout）
- 设备绑定测试（bind / current）

OCR：
- OCR API 或本地 OCR 服务测试
- OCR 历史记录写入测试

使用统计和 Provider：
- usage_events 写入测试
- provider_call_log 写入测试

安全：
- 前端无 API Key 泄露检查
- 前端无直连第三方 AI API 检查
- 客户端不扣点检查

## 测试原则

- 测试命令必须可复现（写完整命令，不写 "运行测试"）
- 失败的测试不能隐藏或标记为通过
- 跳过测试必须说明原因
- 测试输出如实粘贴，不编造
- 未覆盖的风险必须坦白说明
